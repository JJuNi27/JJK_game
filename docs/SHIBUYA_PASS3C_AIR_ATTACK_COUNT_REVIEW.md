# PASS 3C — 공중 입력·타격 횟수 진단

기준 HEAD: `3dff1714dd3ed590df3ae7fb199480043288e3d4`, branch `feat/shibuya-combat-mvp`.
현재 체크포인트 상태: **USER VERIFIED — 사용자 직접 플레이 승인 범위 한정**.
2026-10-19 사용자는 공중 추격·공통 공중 체술·완전 체공·정상 착지와 LMB 3회의 2타 → 2타 → 1타 연계 동작을 직접 확인하고 승인했다. 극단적인 충돌·입력·무적·저프레임 경계는 사용자 승인에 포함하지 않는다. 이 문서의 계측 결과와 경계 검사는 CODEX VALIDATED이며, 전체 승인 범위는 [PASS 3C 체크포인트](SHIBUYA_PASS3C_REVIEW.md#사용자-승인-체크포인트--2026-10-19)를 참조한다.

아래 본문은 횟수 진단 당시의 기록이다. 당시 미커밋·사용자 재검수 안내·staging/commit/push 미실행 문구는 해당 시점의 이력이다. 계측 원본과 기존 실패 기록은 보존한다.

## 결론

한 번의 공중 LMB가 적중 때문에 5타로 복제되는 현상은 재현되지 않았다. 일반 점프와 추격 모두 **1입력 → 1단계 → 이벤트 0, 1 → 최대 피해 12+13**이었다. 히트스톱을 끈 대조군도 동일했다.

반면 유효한 후속 클릭을 포함한 **3입력 → 3단계 → 실제 5타 / 피해 62**는 재현됐다. 단계별 이벤트는 `(1,0), (1,1), (2,0), (2,1), (3,0)`이며 중복된 단계·이벤트 키는 없었다. 세 번째 단계의 마지막 이벤트보다 먼저 총 체공 상한이 만료된다. 당시 사용자의 실제 마우스 입력 기록은 없으므로, 이 재현이 사용자가 보았던 상황과 같았다고 단정하지 않는다.

## 실제 Play Mode 기록

Unity Test Framework의 EnterPlayMode/ExitPlayMode를 사용했다. 기존 `ShibuyaPlayerInput.TestInput`에 클릭의 상승 에지를 주입하여 실제 PlayerInput → TryAttack → 공통 타격 엔진 → Health 경로를 실행했다. Windows 마우스를 직접 조작하거나 사용자의 수동 플레이 입력을 수집한 것은 아니다. 추격 준비용 지상 4타는 계측 시작 전에 완료했으며 아래 피해는 공중 구간만 집계한다.

| 상황 | 공중 클릭 | 수락 단계 | 이벤트 수 | 실제 피해 적용 | 피해 합계 |
|---|---:|---:|---:|---:|---:|
| 일반 점프, 허공 | 1 | 1 | 2 | 0 | 0 |
| 일반 점프, 적중 | 1 | 1 | 2 | 2 | 25 |
| 추격 후, 허공 | 1 | 1 | 2 | 0 | 0 |
| 추격 후, 적중 | 1 | 1 | 2 | 2 | 25 |
| 추격 후 버튼 유지 | 1 | 1 | 2 | 2 | 25 |
| 추격 후 적중, 히트스톱 OFF 대조군 | 1 | 1 | 2 | 2 | 25 |
| 추격 후 적중, 유효 후속 클릭 2회 추가 | 3 | 3 | 5 | 5 | 62 |
| 추격 후 허공, 후속 클릭 1회 추가 | 2 | 1 | 2 | 0 | 0 |

3입력 대조군의 이벤트 실시간은 최초 단계 접수 기준 약 **0.077 / 0.274 / 0.608 / 0.803 / 1.140초**였다. 각 실제 피해에는 같은 단계·이벤트 키가 정확히 한 번만 존재했다. 한 번 클릭의 적중/허공 비교와 히트스톱 대조에서 추가 단계나 추가 피해는 없었다.

## 런타임·데이터 구조

- 지상과 별도인 `Shibuya Aerial Combat.asset`이 존재한다. `ShibuyaAerialCombatDefinition.aerialAttack`은 하나의 `ShibuyaMovesetStep`이며 현재 2개 타격 이벤트를 갖는다. 지상 기본 4단계와 별도 데이터지만 판정 엔진은 공유한다.
- `AerialDefinition`은 캐릭터 무브셋의 공중 설정이 있으면 이를, 없으면 Combat Profile의 공중 설정을 사용한다. 같은 캐릭터의 일반 점프·추격 후 LMB 모두 `TryAirAttack → BeginCommonAirStep`에서 이 **동일한 aerialAttack**을 사용한다.
- `PrepareActiveStep`은 단계 접수 시 이벤트별 방문 기록과 대상 HashSet을 만든다. `UpdateAttack`은 이벤트 시작을 한 번 알리며 활성 구간 동안 판정을 반복해도 대상별 피해는 해당 이벤트에서 한 번만 허용한다. 히트스톱은 이 기록을 초기화하지 않는다.
- 후속 단계는 **별도의 유효한 LMB**가 `BufferCommonAirStep`에 예약된 경우에만 시작한다. 실제 이전 적중·유효 대상·마지막 입력 허용 구간이 필요하다. 체공 잔여 시간, 도착, 적중 그 자체로 후속 공격을 만들지는 않는다. 예약된 입력이 소비되어 다음 단계가 시작되는 것은 자동 입력 생성이 아니다.
- 버튼 유지 입력도 PlayerInput의 `previousAttack` 상승 에지 검사 때문에 새 클릭으로 반복 소비되지 않는다.

## 체공 정책 — 변경 없음

- 최초 공중 LMB 접수 시 준비·활성·회복 동안 수직 속도를 0으로 유지한다.
- `aerialMaxHoverTime = 1.2초`는 최초 공중 공격 접수 시 시작하는 **unscaled 총 상한**이다. 후속 단계·피해·히트스톱으로 갱신하지 않는다.
- 실제 적중 후에는 `aerialLinkInputWindow = 0.12초`의 짧은 후속 입력 대기가 가능하다. 시간만 남아 있다고 공격이 시작되지는 않는다. 허공 공격에는 적중 후 대기가 없다.
- 종료·취소·피격·사망·전투 종료·비활성화·예산/대기 만료 시 높이 유지 및 예약을 해제한다. 피격자 체공은 실제 유효 적중과 합법적인 경직/연계가 유지되는 경우에 한정된다.

## 이동 작성 기능과 한계

현재 공중 `aerialAttack`도 공통 `movements[]`를 사용한다. 전진 클립을 런타임 복제 데이터에만 작성한 대조군에서 **실제 Z 이동 0.4m(허용 오차 0.02m), Y 변화 0.001m 미만**을 확인했다. 기본 에셋의 `movements`는 빈 배열이므로 기본 공중 공격에 작성된 전진 클립은 없다.

현재 가능한 것은 시간·거리·속도 제한이 있는 Forward와 ApproachLastHit, 제한적 수평 회전이다. ApproachLastHit의 목표 벡터와 예측 속도는 Y를 제거한다. 첫 일반 점프 공격에는 추격 대상/직전 공중 적중 대상이 없으므로 처음부터 타깃 접근이 항상 가능한 것도 아니다. 공중 공격은 `AdvanceMoveset` 경로를 사용하므로 지상용 strike.advanceDistance만 올려 이동을 작성한 것으로 간주하면 안 된다.

**부족한 부분:** 타격별 자유로운 수직/3D 이동 벡터·경로, 독립적인 회전 시퀀스, 서로 다른 공중 후속 단계 배열은 아직 없다. 추격 자체의 3D 이동과 공중 무브셋 내부의 3D 이동 작성 기능을 구분해야 한다.

확장한다면 기존 MovementDefinition에 명시적 로컬/대상 기준 3D 변위와 유한한 이동 예산을 추가하고, 이를 현재 단일 CharacterController 이동 경로와 체공의 명시적 수직 이동 예외로 연결하는 작은 확장부터 검토한다. 서로 다른 공중 단계가 필요할 때만 공중 단계 배열/진행 정책을 데이터에 추가하고 타격 엔진은 공유한다. **이번에는 구현하지 않았다.**

## 검증·보존

- 신규 실제 Play Mode 진단: **단일 실행 9 PASS / 0 FAIL / 0 SKIP**, discovery·execution 로그·XML 모두 생성.
- 기존 126개는 이전 네 실행의 최신 고유 결과 **126 PASS** 근거를 보존했다. 이번에 중복 버그나 런타임 변경이 없어 전체 126개는 재실행하지 않았다. 신규 9개와 합쳐 단일 135개 실행이라고 표현하지 않는다.
- C# compile 실패 없음. 최종 현재 Console error 0, warning 1(`Deleting invalid font reference.`). 중간에 지원하지 않는 Pipeline `refresh` 명령 호출로 도구 오류 1건이 기록됐으며 이후 지원되는 `recompile`로 컴파일했다. 이 기록은 지우지 않았다. 게임 런타임/컴파일 오류와 구분한다.
- 검사 전 기존 파일 1,064개의 SHA-256과 최종 내용을 비교해 **기존 파일 변경 0** 확인. 전투 런타임·모션·공중/지상 에셋·Scene·Prefab·Packages·ProjectSettings·Gojo/VFX·기존 .meta를 수정하지 않았다.
- 기본 피해 20/20/20/25, Dummy HP 1000, Player HP 100, 어퍼컷 높이 5.5, 강타 히트스톱 0.065, 공중 피해 12+13과 GUID 보존. 최종 미저장 Scene/ScriptableObject 없음, Play Mode 종료, Time.timeScale 1.
- 임시 AutoTick true/0ms는 검사 후 기존 true/16ms 및 원래 SessionState 저장 상태로 복구한다. staging/commit/push 없음.
