# JJK Game 프로젝트 인수인계서

> 새 ChatGPT 대화에서는 저장소의 `README.md`, 이 문서, `docs/CANON_SKILL_RULES.md`, `docs/AUDIO_SETUP.md`, `unity/README.md`와 최신 코드를 먼저 읽고 현재 상태에서 이어간다.

이 문서는 코드 작업 묶음이 끝날 때마다 **사용자가 확인한 상태**, **원격에만 반영된 테스트 전 상태**, **다음 작업**을 분리해 기록하는 단일 인수인계 기준 문서다.

## 1. 프로젝트와 환경

- 프로젝트명/컨셉: **주술사 되어보기**
- 사용자: 박민준
- GitHub: `JJuNi27/JJK_game`
- 브랜치: `master`
- 로컬 저장소: `D:\GitHub\JJK_game`
- Unity 프로젝트: `D:\GitHub\JJK_game\unity`
- Unity: 6.3 LTS `6000.3.20f1`, URP
- 현재 우선순위: Unity 고죠 전투 프로토타입 안정화

작업 루프:

```text
Assistant가 master 수정
→ 사용자가 git pull origin master
→ 사용자 Unity에서 실행
→ 화면·오류·조작감 전달
→ 문제 수정과 다음 계획 작업을 함께 진행
```

사용자 pull 명령:

```powershell
cd D:\GitHub\JJK_game
git pull origin master
```

Assistant는 Unity를 직접 실행·컴파일했다고 주장하지 않는다.

## 2. 제작 원칙

1. 원작 만화와 공식 애니메이션·극장판 설정을 우선한다.
2. `OFFICIAL_CONFIRMED`, `GAME_ORIGINAL`, `INTERPRETATION_PENDING`을 구분한다.
3. 원작에 없는 적중 횟수, 게이지, 쿨타임, 소비량과 키를 원작 조건처럼 설명하지 않는다.
4. 기능 검증용 VFX와 최종 연출을 구분한다.
5. 서로 강하게 연결된 2~3개 작업은 묶어서 구현하되 테스트 항목은 분리한다.
6. 사용자가 문제를 발견하면 그 문제를 고치면서 다음 계획 작업도 함께 진행한다.
7. 작업 묶음이 끝나면 이 문서를 반드시 갱신한다.

세부 원작 규칙: `docs/CANON_SKILL_RULES.md`

## 3. Python/Pygame 완료 상태

아래 네 캐릭터의 영역전개 입력과 일본어 Vosk 음성인식을 사용자가 정상 확인했다.

```text
고죠: 무량공처
스쿠나(이타도리 몸): 복마어주자
후시구로 메구미: 감합암예정
옷코츠 유타(본편 2학년): 진안상애
```

현재 개발 우선순위는 Python 캐릭터 추가보다 Unity 전투다.

## 4. Unity 공통 조작

```text
WASD   이동
SPACE  회피 및 짧은 무적
TAB    가까운 적 락온 → 다음 적 → 해제
LMB    3단 기본 공격
Q      고죠 술식순전 「창」
E      고죠 술식반전 「혁」
R      고죠 허식 「자」
V      영역전개 입력 시작
X      진행 중인 영역 입력 취소
ENTER  승패 후 재시작
```

입력 정의: `unity/Assets/Scripts/Core/CombatInputBindings.cs`

## 5. 사용자가 정상 확인한 Unity 상태

### 기본 전투

- WASD 이동
- 기본 공격 1→2→3타
- `ATTACK CHAIN`과 실제 `HIT COMBO` 분리
- 주령 추적, 공격 예고, `DODGE!`
- SPACE 회피와 무적
- HP HUD, 승패, ENTER 재시작
- 확장 맵과 안전벽
- 낙사 즉사

### 다중 적과 락온

- 주령 두 마리 런타임 생성
- 주령별 체력바와 `CURSES LEFT`
- 모든 주령 처치 시 승리
- TAB으로 A → B → 해제
- 락온 대상 우선 공격과 허식 자 조준

### 고죠 술식

- Q 창은 락온 대상 근처 또는 정면 수렴점
- 약 0.24초 시전 후 약 0.95초 유지되는 수렴장
- 한 대상 피해는 한 번, 인력은 반복
- E 혁은 약 0.30초 시전 후 실제 이동하는 발사체
- 일렬로 선 여러 적 관통
- 창→혁 적중 보너스
- 허식 자 준비는 적중이 아니라 Q/E 사용 자체
- R 허식 「자」
- V 장인 입력과 무량공처

### 사운드와 화면 피드백

사용자가 다음을 정상 확인했다.

- 기본 공격 휘두름과 적중음
- 고죠 피격음
- 무량공처 발동음
- 무량공처의 출렁이는 임시 영역 효과
- 승리와 패배 사운드
- 카메라 흔들림과 화면 플래시

사용자 피드백:

- **3타 강화 타격음은 1·2타와 차이가 잘 느껴지지 않았다.**
- 다음 원격 작업에서 별도 저음 충격음과 더 강한 흔들림/플래시로 보강했다.

## 6. 현재 원격 저장소의 새 작업 — 사용자 테스트 필요

아래 묶음은 `master`에 반영됐지만 아직 사용자가 pull 후 실행하지 않았다.

### 6-1. 공통 주력 자원

새 파일:

```text
unity/Assets/Scripts/Core/CursedEnergyController.cs
```

현재 `GAME_ORIGINAL` 수치:

```text
최대 주력 100
초당 회복 12
사용 후 회복 지연 0.8초

Q 창 16
E 혁 24
R 허식 자 45
V 무량공처 60
```

동작:

- 체력 패널 아래 보라색 주력 바 표시
- 기술 사용 시 소비
- 주력 부족 시 기술 시작 차단과 필요량 표시
- 무량공처는 V 시작 시 보유량을 확인하고 입력 성공 시 실제 소비
- 쿨타임, 자 준비 조건과 주력 조건은 독립 판정

정확한 수치는 원작 공식 숫자가 아니라 플레이 테스트용이다.

### 6-2. 공통 행동 상태 판정

새 파일:

```text
unity/Assets/Scripts/Core/CombatActionGate.cs
```

상태:

```text
Normal
Dodging
TechniqueCasting
DomainInput
DomainActive
Disabled
```

적용:

- 회피 중 기본 공격·Q/E/R/V 시작 차단
- Q/E 시전 중 기본 공격·회피·R/V 시작 차단
- 영역 입력·전개 중 다른 행동 차단
- 기존 여러 스크립트의 중복 조건을 공통 판정기로 연결

### 6-3. 3타 피드백 강화

- 3타에 일반 타격음과 별도 저음·노이즈 충격음을 겹침
- 카메라 흔들림을 크게 강화
- 연보라색 화면 플래시 강화
- 로컬 교체 슬롯 `BasicFinisher.wav` 추가

핵심 파일:

```text
unity/Assets/Scripts/Core/PrototypeCombatAudio.cs
```

## 7. 이번 작업 테스트 순서

```text
1. 플레이어 체력 패널 아래 CURSED ENERGY 100/100 바가 보이는지
2. Q 사용 시 16, E 사용 시 24가 줄어드는지
3. 약 0.8초 뒤 초당 12 정도로 자동 회복하는지
4. Q/E 연타로 주력이 부족해지면 기술이 발동하지 않는지
5. 부족할 때 주력 바와 스킬 UI에 필요량이 표시되는지
6. 허공에 Q와 E를 사용한 뒤 R을 쓰면 45가 소비되는지
7. 주력 60 미만에서 V를 누르면 영역 입력이 시작되지 않는지
8. 주력 60 이상에서 장인 입력 성공 시 60이 소비되는지
9. 회피 중 좌클릭/Q/E/R/V가 새로 시작되지 않는지
10. Q/E 시전 중 기존 행동 잠금이 유지되는지
11. 3타 적중음과 흔들림이 1·2타보다 확실히 강해졌는지
12. 기존 창·혁·자·무량공처·승패가 정상인지
13. Console에 빨간 컴파일 오류가 없는지
```

## 8. 알려진 한계

- 캐릭터 모델과 애니메이션 없음
- LineRenderer와 Primitive 기반 임시 VFX
- 카메라 회전 락온과 수동 조준 없음
- 주령은 단순 직선 추적
- 기본 공격 자체의 공격 프레임 상태는 아직 공통 행동 상태에 포함되지 않음
- 주력 수치는 최종 밸런스가 아님
- 술식 번아웃과 반전술식 회복 없음
- 원본 주술회전 음원은 저장소에 포함하지 않음

## 9. 새 작업이 정상일 때 다음 우선순위

```text
술식 번아웃 기반
- 영역전개 종료 후 Q/E/R 일시 봉인
- 번아웃 HUD
- 향후 반전술식 회복을 붙일 수 있는 상태 구조

전투 시스템
- 캐릭터 공통 스킬 인터페이스
- 캐릭터별 자원 설정
- 고죠 프로토타입 안정화

그 다음
- 두 번째 캐릭터의 Unity 설계
- 원작 조건 검토 후 스쿠나 후보
```

## 10. 새 채팅에서 Assistant가 먼저 할 일

1. 이 문서를 읽는다.
2. 사용자가 6번 작업을 pull하고 테스트했는지 확인한다.
3. 오류가 있으면 고치면서 다음 작업도 진행한다.
4. 원작 조건은 공식 자료와 `docs/CANON_SKILL_RULES.md`를 다시 확인한다.
5. 작업 후 이 문서를 반드시 갱신한다.
