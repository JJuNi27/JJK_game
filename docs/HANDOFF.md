# JJK Game 프로젝트 인수인계서

> 새 ChatGPT 대화에서는 저장소의 `README.md`, 이 문서, `docs/CANON_SKILL_RULES.md`, `docs/ADAPTATION_REFERENCES.md`, `docs/AUDIO_SETUP.md`, `unity/README.md`와 최신 코드를 먼저 읽고 현재 상태에서 이어간다.

이 문서는 코드 작업 묶음이 끝날 때마다 **사용자가 확인한 상태**, **원격에만 반영된 테스트 전 상태**, **다음 작업**을 분리해 기록하는 단일 인수인계 기준 문서다.

## 1. 프로젝트와 환경

- 프로젝트명/컨셉: **주술사 되어보기**
- 사용자: 박민준
- GitHub: `JJuNi27/JJK_game`
- 브랜치: `master`
- 로컬 저장소: `D:\GitHub\JJK_game`
- Unity 프로젝트: `D:\GitHub\JJK_game\unity`
- Unity: 6.3 LTS `6000.3.20f1`, URP
- 현재 우선순위: Unity 고죠 전투 프로토타입 안정화

작업 루프:

```text
Assistant가 master 수정
→ 사용자가 git pull origin master
→ 사용자 Unity에서 실행
→ 화면·오류·조작감 전달
→ 문제 수정과 다음 계획 작업을 함께 진행
```

사용자 pull 명령:

```powershell
cd D:\GitHub\JJK_game
git pull origin master
```

Assistant는 Unity를 직접 실행·컴파일했다고 주장하지 않는다.

## 2. 제작 원칙

1. 만화 본편·공식 팬북·공식 애니메이션·극장판 설정을 최우선으로 한다.
2. `OFFICIAL_CONFIRMED`, `ADAPTATION_REFERENCE`, `GAME_ORIGINAL`, `INTERPRETATION_PENDING`을 구분한다.
3. 팬텀 퍼레이드는 공식 라이선스 게임의 전투게임식 번역 참고자료로 사용한다.
4. 팬텀 퍼레이드의 모션·카메라·VFX·사운드·자원 표현을 참고하되 원본 자산을 복사하지 않는다.
5. 원작에 없는 적중 횟수, 게이지, 쿨타임, 소비량과 키를 원작 조건처럼 설명하지 않는다.
6. 기능 검증용 VFX와 최종 연출을 구분한다.
7. 서로 강하게 연결된 2~3개 작업은 묶어서 구현하되 테스트 항목은 분리한다.
8. 사용자가 문제를 발견하면 그 문제를 고치면서 다음 계획 작업도 함께 진행한다.
9. 작업 묶음이 끝나면 이 문서를 반드시 갱신한다.

관련 문서:

```text
docs/CANON_SKILL_RULES.md
docs/ADAPTATION_REFERENCES.md
docs/AUDIO_SETUP.md
```

## 4. Unity 공통 조작

```text
WASD   이동
SPACE  회피 및 짧은 무적
TAB    가까운 적 락온 → 다음 적 → 해제
LMB    3단 기본 공격
Q      고죠 술식순전 「창」
E      고죠 술식반전 「혁」
R      고죠 허식 「자」
V      영역전개 입력 시작
X      진행 중인 영역 입력 취소
ENTER  승패 후 재시작
```

입력 정의: `unity/Assets/Scripts/Core/CombatInputBindings.cs`

## 5. 사용자가 정상 확인한 Unity 상태

### 기본 전투·맵

- WASD 이동
- 기본 공격 1→2→3타
- `ATTACK CHAIN`과 실제 `HIT COMBO` 분리
- 주령 추적, 공격 예고, `DODGE!`
- SPACE 회피와 무적
- HP HUD, 승패, ENTER 재시작
- 약 65×65 확장 맵과 안전벽
- 낙사 즉사

### 다중 적과 락온

- 주령 두 마리 런타임 생성
- 주령별 체력바와 `CURSES LEFT`
- 모든 주령 처치 시 승리
- TAB으로 A → B → 해제
- 락온 대상 우선 공격과 허식 자 조준

### 고죠 술식

- Q 창은 락온 대상 근처 또는 정면 수렴점
- 약 0.24초 시전 후 약 0.95초 유지되는 수렴장
- 한 대상 피해는 한 번, 인력은 반복
- E 혁은 약 0.30초 시전 후 실제 이동하는 관통 발사체
- 창→혁 적중 보너스
- 허식 자 준비는 적중이 아니라 Q/E 사용 자체
- R 허식 「자」
- V 장인 입력과 무량공처

### 주력·행동·피드백

사용자가 직전 묶음 전체가 적용됐다고 확인했다.

- 최대 100 주력 바와 자동 회복
- 기존 Q 16 / E 24 / R 45 / V 60 소비 테스트
- 주력 부족 시 기술 차단과 안내
- 회피·술식 시전·영역 입력 중 행동 충돌 차단
- 기본 공격·피격·회피·창·혁·자·무량공처·승패 사운드
- 무량공처의 출렁이는 임시 영역 효과
- 카메라 흔들림과 화면 플래시
- 3타 전용 저음 충격음과 강화 피드백

## 6. 현재 원격 저장소의 새 작업 — 사용자 테스트 필요

아래 묶음은 `master`에 반영됐지만 아직 사용자가 pull 후 실행하지 않았다.

### 6-1. 캐릭터별 주력 프로필

핵심 파일:

```text
unity/Assets/Scripts/Core/CursedEnergyController.cs
docs/ADAPTATION_REFERENCES.md
```

준비된 프로필:

```text
Standard
- 최대 100
- 일반 소비 효율

SixEyesEfficiency
- 고죠 전용
- 최대 100
- 내부 기본 소비량의 1%를 올림 처리
- 기술당 최소 소비 1

SukunaVastReserve (향후)
- 최대 300 대용량형 출발점

YutaLargeReserve (향후)
- 최대 150 대용량형 출발점
```

현재 고죠의 실제 소비:

```text
Q 창 1
E 혁 1
R 허식 자 1
V 무량공처 1
```

주력 HUD에는 `SIX EYES · 육안 효율`이 표시된다. 내부 기본 소비량은 캐릭터 간 비교 기준으로 남기고 실제 소비만 프로필이 보정한다.

### 6-2. 술식 번아웃

새 파일:

```text
unity/Assets/Scripts/Core/TechniqueBurnoutController.cs
```

현재 동작:

- 무량공처가 정상 종료된 뒤 약 5초 번아웃 시작
- 번아웃 중 Q/E/R/V 봉인
- 이동, 기본 공격과 회피는 사용 가능
- 왼쪽 HUD에 남은 시간 표시
- 향후 반전술식 조기 회복용 `RestoreTechniqueEarly()` 훅 제공
- `CombatActionGate`가 번아웃을 기술·상위기·영역 시작 조건에 반영

원작의 영역 후 생득술식 번아웃 개념을 사용하며, 정확한 5초는 `GAME_ORIGINAL` 테스트 수치다.

### 6-3. 참고자료 정책

- 팬텀 퍼레이드를 모션, 애니메이션 타이밍, VFX, 카메라, 사운드와 자원 번역 참고자료로 공식 등록
- 원작 설정과 충돌하면 만화·공식 애니 설정 우선
- 게임 원본 자산은 저장소에 복사하지 않음
- 유타 최대 주력 150 사례와 고죠 소비 0~1/1 사례를 프로필 설계 참고로 기록

## 7. 이번 작업 테스트 순서

```text
1. git pull 후 Console에 빨간 오류가 없는지
2. 주력 바에 SIX EYES · 육안 효율이 표시되는지
3. Q를 사용하면 16이 아니라 1만 감소하는지
4. E를 사용하면 1만 감소하는지
5. 허공에 Q/E를 사용해 R을 준비한 뒤 R도 1만 감소하는지
6. 무량공처 성공 발동 시 V도 1만 감소하는지
7. 무량공처가 약 3초 뒤 끝나면 술식 번아웃 HUD가 뜨는지
8. 번아웃 약 5초 동안 Q/E/R/V가 발동하지 않는지
9. 번아웃 중 이동·좌클릭 기본 공격·SPACE 회피는 가능한지
10. 번아웃 종료 뒤 Q/E/R/V가 다시 사용 가능한지
11. 기존 창·혁·자·무량공처·사운드·승패가 정상인지
```

## 8. 알려진 한계

- 캐릭터 모델과 애니메이션 없음
- LineRenderer와 Primitive 기반 임시 VFX
- 카메라 회전 락온과 수동 조준 없음
- 주령은 단순 직선 추적
- 기본 공격 자체의 공격 프레임 상태는 아직 공통 행동 상태에 포함되지 않음
- 주력 프로필 수치는 최종 밸런스가 아님
- 반전술식으로 번아웃을 조기 회복하는 실제 입력은 아직 없음
- 무하한 상시 방어와 이를 무시하는 공격 규칙 없음
- 원본 주술회전·팬텀 퍼레이드 자산은 저장소에 포함하지 않음

## 10. 새 채팅에서 Assistant가 먼저 할 일

1. 이 문서를 읽는다.
2. 사용자가 6번 작업을 pull하고 테스트했는지 확인한다.
3. 오류가 있으면 고치면서 다음 작업도 진행한다.
4. 원작 조건은 `docs/CANON_SKILL_RULES.md`, 공식 게임 참고는 `docs/ADAPTATION_REFERENCES.md`를 확인한다.
5. 작업 후 이 문서를 반드시 갱신한다.
