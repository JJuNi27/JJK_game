# JJK Game 프로젝트 인수인계서

> 이 문서는 새 ChatGPT 대화나 새로운 개발자가 저장소 링크만 전달받아도 기존 대화의 맥락과 개발 결정을 이해하고 바로 이어서 작업할 수 있도록 작성한 기준 문서다.
>
> 새 대화에서 사용자가 `이 깃허브 읽고 우리 하던 거 계속하자`라고 말하면 **README, 이 문서, 현재 코드를 먼저 읽고 최신 저장소 상태를 기준으로 작업을 이어간다.**

---

## 1. 프로젝트 한 줄 정의

주술회전의 **술식 선언, 장인(손동작), 영역전개, 공간 변화 연출**을 실제 게임 입력 시스템으로 옮기는 개인 프로젝트다.

현재는 완성 게임을 바로 만들지 않고, 프로젝트의 가장 독특한 요소인 **장인 커맨드 입력의 재미와 성공/실패 판정**을 Python + Pygame 프로토타입으로 먼저 검증하고 있다.

장기적으로는 Unity 같은 게임 엔진에서 캐릭터를 선택하고 봇과 싸우는 전투 게임으로 확장할 계획이다.

## 3. 프로젝트가 처음 구상된 과정

최초 아이디어는 웹캠으로 실제 장인 손동작을 인식해, 무량공처 등의 영역전개 이펙트를 출력하는 컴퓨터 비전 프로젝트였다.

초기 인식 대상으로 생각한 영역은 다음 네 가지다.

```text
무량공처
복마어주자
감합암예정
진안상애
```

원래 계획은 MediaPipe Hand Landmarker로 손가락 landmark를 추출하고, 직접 수집한 데이터로 RandomForest 분류 모델을 학습하는 방식이었다.

하지만 현재 사용자의 웹캠이 고장났고, 아이폰을 PC 카메라로 연결할 장치나 촬영 거치대도 없다. 따라서 손동작 AI 인식은 폐기한 것이 아니라 **후순위 확장 기능**으로 미뤘다.

현재는 실제 장인을 마우스·키보드 커맨드로 번역하고, 나중에 카메라가 생기면 입력 모듈만 교체할 수 있도록 설계하는 방향이다.

## 4. 확정된 핵심 방향

### 4.1 메인 전투 모드

- 전투 전에 캐릭터를 선택한다.
- 선택한 캐릭터의 술식과 영역만 사용할 수 있다.
- 설정에 없는 영역이나 기술을 임의로 다른 캐릭터에게 주지 않는다.
- 장기적으로 Unity에서 플레이어 캐릭터와 봇이 싸우는 전투를 구현한다.

### 4.2 자유 모드 / 연습장

- 캐릭터 제한 없이 장인 커맨드를 연습한다.
- 성공률, 입력 시간, 타이밍 정확도 등을 확인한다.
- 영역 이펙트 감상과 음성·카메라 입력 테스트 공간으로 사용한다.
- 현재 Pygame 프로토타입은 이 자유 연습장의 원형이다.

### 4.3 일반 술식

현재는 영역전개부터 구현하지만, 최종 프로젝트에는 일반 술식도 추가할 계획이다.

예정된 기본 흐름:

```text
평상시 커맨드 입력
→ 캐릭터 고유 술식 발동

“영역전개” 음성 선언
→ 영역 준비 상태
→ 캐릭터 고유 장인 커맨드
→ 영역전개 발동
```

일반 술식은 영역전개 MVP가 안정된 이후 추가한다.

### 4.4 음성인식

- 최종적으로 사용자가 `영역전개` 또는 `료이키 텐카이`라고 말하면 영역 준비 상태에 들어가게 한다.
- 현재 프로토타입에서는 음성 대신 `V` 키를 사용한다.
- 디버깅과 마이크 미사용 환경을 위해 `V` 키 대체 입력은 나중에도 유지한다.
- 음성은 어떤 캐릭터의 영역인지 결정하지 않는다. 캐릭터 선택 또는 현재 컨텍스트가 영역을 결정한다.

### 4.5 카메라 입력

카메라가 생기면 다음 구조로 추가한다.

```text
현재: MouseSealInput
미래: CameraSealInput
```

게임·영역·이펙트 로직은 유지하고 장인 입력부만 교체하거나 선택 가능하게 한다.

## 5. 주술회전 설정 운영 원칙

프로젝트는 만화 원작과 공식 애니·극장판의 설정과 연출을 통합한다.

- 만화 버전/애니 버전을 별도 게임 모드로 복잡하게 나누지 않는다.
- 공식 애니·극장판에서 추가된 연출과 기술도 프로젝트에 포함할 수 있다.
- 예: 유타는 극장판 `주술회전 0`에서 흑섬을 사용했으므로 프로젝트에서 흑섬 사용 가능 캐릭터다.
- 단, 팬 해석과 공식 설정을 구분한다.
- 게임 밸런스를 위해 새로 만든 규칙은 설정 사실인 것처럼 설명하지 않고 게임 각색으로 표시한다.

### 캐릭터 추가 절차

캐릭터를 구현하기 전에 설정 카드를 작성하고 사용자 검토 후 확정한다.

설정 카드 항목:

```text

생득술식
파생 기술
영역전개
장인 형태

특수 예외

게임에서 구현할 범위
게임 각색 부분
사용자 검토 결과
```

### 현재 검토 완료 캐릭터

고죠 사토루 설정 카드는 대화에서 1차 검토를 통과했다.


현재 프로토타입에서는 무량공처 장인 커맨드만 구현한다.

## 6. 현재 무량공처 커맨드 디자인

설계 목적은 임의의 ABC 입력이 아니라 **고죠의 한 손 장인과 정밀 제어를 마우스 한 손 조작으로 번역하는 것**이다.

현재 입력:

```text
1. V 키를 눌러 영역전개 준비 상태 진입
2. 마우스 오른쪽 버튼 누르고 유지
3. 오른쪽 버튼을 유지한 채 제한 시간 안에 왼쪽 클릭
4. 초록색 타이밍 구간에서 오른쪽 버튼 해제
5. 성공 시 무량공처 임시 이펙트 발동
```

입력의 의미:

| 입력 | 게임 속 의미 |
|---|---|
| V 또는 미래의 음성 선언 | 영역 구축 시작 |
| 우클릭 유지 | 주력 집중 및 장인 준비 |
| 좌클릭 | 검지·중지 장인 결합 |
| 타이밍 대기 | 무량공처 안정화 |
| 우클릭 해제 | 영역 개방 |

현재 수치는 프로토타입 값이며, 사용자 플레이 피드백에 따라 조절한다.

## 7. 현재 구현 상태

사용자가 로컬에서 실행해 다음 기능이 정상 작동함을 확인했다.

- Pygame 창 실행
- `V` 키로 영역 준비 상태 진입
- 우클릭 유지 → 좌클릭 → 타이밍 해제 커맨드
- 성공 판정
- 잘못 입력했을 때 실패 판정
- 임시 무량공처 이펙트
- 한국어 연습 UI와 한국어 실패 사유
- `R` 키 초기화
- `ESC` 종료
- Windows의 한글 폰트 자동 탐색

즉, 첫 번째 장인 입력 프로토타입은 기능적으로 동작하는 상태다.

### 현재 상태 머신

```text
NORMAL
→ DOMAIN_READY
→ WAIT_LEFT_CLICK
→ RELEASE_TIMING
→ DOMAIN_ACTIVE

실패 시
→ FAILED
→ 일정 시간 후 NORMAL
```

화면에서는 위 내부 상태를 한국어 이름으로 표시한다.

## 9. 로컬 실행 방법

이미 저장소를 받은 상태:

```powershell
git pull origin master
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python main.py
```

PowerShell 실행 정책 때문에 가상환경 활성화가 안 되면 VS Code의 Command Prompt 터미널에서:

```bat
.venv\Scripts\activate.bat
python main.py
```

### 조작법

```text
V: 영역 준비
우클릭 유지: 장인 준비
우클릭 유지 중 좌클릭: 장인 결합
초록색 구간에서 우클릭 해제: 발동 판정
R: 초기화
ESC: 종료
```

## 11. 바로 다음 작업 우선순위

사용자와 마지막으로 합의한 다음 작업은 **입력 모듈 분리**다.

현재 `DomainController`가 Pygame의 키보드·마우스 이벤트를 직접 받는 구조를 단계적으로 다음처럼 분리한다.

```text
KeyboardDomainTrigger
- 현재 V 키 감지
- 미래에 VoiceDomainTrigger와 교체·병행 가능

MouseSealInput
- 현재 우클릭·좌클릭·해제 입력 감지
- 미래에 CameraSealInput과 교체·병행 가능

DomainController
- 구체적인 입력 장치를 몰라도 됨
- 영역 상태 전이와 성공/실패 규칙만 관리
```

### 리팩터링 시 주의사항

- 사용자에게 이미 잘 작동한다고 확인받은 현재 조작감을 깨뜨리지 않는다.
- 한 번에 전체 구조를 과도하게 뜯지 않는다.
- 작은 단계로 분리하고 매 단계마다 로컬 실행을 요청한다.
- 화면에 보이는 한국어 UI는 유지한다.
- 임시 이펙트 품질 개선은 후순위다.
- 음성인식은 입력 모듈 분리 후 추가한다.

권장 다음 순서:

```text
1. 현재 동작 기준점 확인
2. KeyboardDomainTrigger 분리
3. MouseSealInput 분리
4. 기존 DomainController와 연결
5. 사용자가 로컬 회귀 테스트
6. README와 이 문서의 현재 상태 업데이트
7. VoiceDomainTrigger 설계·추가
```

```text
2. docs/HANDOFF.md 전체 읽기
3. 현재 코드(main.py, game/, input/, effects/) 읽기
4. 최신 커밋과 현재 구현이 문서와 다른지 확인
5. 사용자에게 현재 상태와 다음 작업을 짧게 요약
6. 인수인계서의 “바로 다음 작업 우선순위”부터 진행
```

문서와 코드가 충돌하면 **최신 코드와 사용자의 최신 발언이 우선**이다.

설정 관련 기능을 새로 만들 때는 먼저 공식 자료를 조사하고 캐릭터 설정 카드를 작성한 후 사용자 검토를 받는다.

## 14. 문서 유지 규칙

큰 결정이나 단계가 바뀌었을 때 이 문서를 업데이트한다.

업데이트가 필요한 예:

```text
입력 모듈 분리 완료
음성인식 방식 확정
Unity 프로젝트 생성
첫 캐릭터 전투 구현
카메라 손동작 인식 재개
새 캐릭터 설정 카드 승인
```

사소한 UI 문구 변경이나 작은 버그 수정까지 매번 적을 필요는 없다. 그런 기록은 Git 커밋으로 관리한다.
