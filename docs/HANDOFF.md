# JJK Game 프로젝트 인수인계서

> 새 ChatGPT 대화에서 사용자가 저장소 링크와 함께 `이 깃허브 읽고 우리 하던 거 계속하자`라고 말하면 **README, 이 문서, 캐릭터 설정 카드, 최신 코드를 먼저 읽고 현재 상태에서 이어간다.**

## 1. 프로젝트 정의

주술회전의 **술식 선언, 장인(손동작), 영역전개, 공간 변화 연출**을 게임 입력 시스템으로 옮기는 개인 프로젝트다.

현재는 Python + Pygame으로 캐릭터별 장인 커맨드의 조작감과 성공·실패 판정을 먼저 검증한다. 장기적으로 Unity에서 캐릭터를 선택하고 봇과 싸우는 3D 전투 게임으로 확장한다.

## 2. 사용자와 협업 방식

- 사용자: 박민준
- 저장소: `JJuNi27/JJK_game`
- 기본 브랜치: `master`
- 환경: Windows + VS Code
- 화면 문구는 가능한 한 한국어 사용
- 설정 사실은 조사하고, 공식 설정과 게임 각색을 구분
- 사용자가 직접 수정했다면 먼저 GitHub에 push하도록 안내

```text
Assistant가 GitHub 수정
→ 사용자 git pull origin master
→ 사용자 python main.py 실행
→ 화면·오류·조작감 전달
→ Assistant가 다시 수정
```

## 3. 장기 방향

### 메인 전투 모드

- 캐릭터 선택
- 선택 캐릭터의 술식과 영역만 사용
- Unity에서 플레이어와 봇 전투
- 첫 봇은 강화학습이 아니라 상태 머신

첫 Unity MVP 후보:

```text
플레이어: 고죠
상대: 단순 주령 봇 1마리
맵: 작은 전투장
기능: 이동, 기본 공격, 체력, 봇 추적·공격, 무량공처, 승패
```

### 자유 연습장

- 캐릭터별 장인 연습
- 성공률·연속 성공·타이밍 오차
- 음성·마우스·미래 카메라 입력 테스트
- 현재 Pygame 프로그램이 이 연습장의 원형

### 카메라 입력

초기 계획은 MediaPipe Hand Landmarker와 직접 수집한 데이터로 실제 장인을 인식하는 것이었다. 웹캠이 고장 나 후순위로 미뤘으며 폐기하지 않았다.

```text
현재: 마우스·키보드 장인
미래: CameraSealInput
```

## 5. 공통 영역 음성 규칙

모든 영역전개 캐릭터는 음성으로 **`료이키 텐카이`까지만** 말한다.

```text
료이키 텐카이
→ DOMAIN_READY
→ 선택 캐릭터의 고유 장인 커맨드
→ 해당 캐릭터의 영역 발동
```

영역명은 추가로 말하지 않는다. 선택한 캐릭터와 장인 성공 결과가 발동 영역을 결정한다.

현재 음성인식:

- Vosk + sounddevice
- 일본어 소형 모델 `vosk-model-small-ja-0.22`
- 확정 결과만 사용
- 허용 문구 전체 일치
- 평균 신뢰도 88% 이상
- V 키는 항상 대체 입력으로 유지
- 사용자가 로컬에서 `료이키 텐카이` 인식 정상 확인

## 7. 스쿠나(이타도리) 확정 범위

설정 카드: [`docs/characters/sukuna.md`](characters/sukuna.md)

사용자 결정:

- 첫 구현은 이타도리 유지 몸
- 몸 형태별 스쿠나는 추후 별도 캐릭터
- 십종영법술 미포함
- 푸가 포함
- 세계를 가르는 참격 미포함
- 영역 음성은 `료이키 텐카이`까지만
- 영역명 `복마어주자`는 말하지 않음

추후 별도 슬롯:

```text
스쿠나(이타도리)
스쿠나(메구미)
스쿠나(헤이안 본체)
```

## 8. 스쿠나 양손 장인 설계안

고죠와 다른 조작감을 위해 실제로 왼손과 오른손을 함께 사용한다.

```text
료이키 텐카이 또는 V
→ 왼손 E 키 유지
→ E를 유지한 채 오른손으로 좌·우클릭을 거의 동시에 누르고 유지
→ 목표 타이밍에 좌·우클릭을 거의 동시에 해제
→ 복마어주자 발동
```

초기 후보 수치:

```text
E 입력 후 양쪽 마우스 완성 제한: 0.70초
좌·우클릭 누름 동시 인정: 0.18초
목표 유지 시간: 0.85초
허용 오차: ±0.22초
좌·우클릭 해제 동시 인정: 0.18초
```

E 키가 장인의 한쪽 손, 마우스 양 버튼이 다른 쪽 손을 표현한다. 영역 준비 상태에서만 E를 장인 전용으로 사용한다. 너무 어렵다면 동시 입력·해제 인정 간격을 늘린다.

아직 코드 구현 전이며 스쿠나 슬롯은 잠금 상태다.

## 9. 현재 구현 상태

사용자가 로컬 확인 완료:

- Pygame 실행
- 캐릭터 선택
- 고죠 클릭 / `1` / `Enter`
- `B`로 선택 화면 복귀
- 일본어 음성
- 고죠 장인 성공·실패
- 임시 무량공처
- 연습 통계
- 캐릭터 카드 자동 줄바꿈
- 긴 문구가 카드 밖으로 침범하지 않음

현재 캐릭터 선택:

- 고죠: 선택 가능
- 스쿠나(이타도리): 설정 확정, 양손 커맨드 구현 중, 잠금
- 세 번째 슬롯: 미정

## 11. 바로 다음 작업

**캐릭터별 장인 컨트롤러 구조 분리 후 스쿠나 양손 커맨드 구현**이다.


- 현재 잘 되는 고죠 조작을 깨지 않는다.
- 한 번에 전투나 일반 술식까지 넓히지 않는다.
- 스쿠나 이펙트는 임시 코드 그림이면 충분하다.
- 첫 테스트는 성공·실패 판정과 양손 조작감 확인이 목표다.
