# JJK Game 프로젝트 인수인계서

> 새 ChatGPT 대화에서는 저장소의 `README.md`, 이 문서, `docs/CANON_SKILL_RULES.md`, `docs/AUDIO_SETUP.md`, `unity/README.md`와 최신 코드를 먼저 읽고 현재 상태에서 이어간다.

이 문서는 코드 작업 묶음이 끝날 때마다 현재 테스트 상태, 새 변경, 다음 작업과 주의점을 갱신하는 **단일 인수인계 기준 문서**다.

## 1. 프로젝트 정의

프로젝트명/컨셉은 **주술사 되어보기**다.

주술회전의 술식 선언, 장인(손동작), 영역전개와 전투 연출을 실제 입력 시스템으로 옮기는 개인 프로젝트다.

현재 두 축이 존재한다.

```text
Python + Pygame
- 캐릭터별 영역전개 입력 검증
- 일본어 음성인식
- 성공·실패와 연습 통계

Unity + C#
- 실제 이동·공격·회피
- 주령 봇 전투
- 일반 술식·상위기·영역전개
- 향후 Python 음성과 Unity 연결
```

현재 우선순위는 **Unity 고죠 전투 프로토타입 안정화**다.

## 2. 사용자와 작업 방식

- 사용자: 박민준
- GitHub 저장소: `JJuNi27/JJK_game`
- 작업 브랜치: `master`
- 사용자 로컬 저장소: `D:\GitHub\JJK_game`
- Unity 프로젝트: `D:\GitHub\JJK_game\unity`
- Unity: 6.3 LTS `6000.3.20f1`, URP
- 화면 문구는 가능한 한 한국어

작업 루프:

```text
Assistant가 master 수정
→ 사용자가 git pull origin master
→ 사용자 컴퓨터의 Unity에서 실행
→ 화면·오류·조작감 전달
→ 문제 수정과 다음 계획 작업을 함께 진행
```

사용자 명령:

```powershell
cd D:\GitHub\JJK_game
git pull origin master
```

Assistant는 Unity를 직접 실행·컴파일했다고 주장하지 않는다. 실제 실행 확인은 사용자가 담당한다.

## 3. 구현 운영 원칙

1. 원작 만화와 공식 애니메이션·극장판 설정을 우선한다.
2. 공식 조건은 `OFFICIAL_CONFIRMED`, 게임용 각색은 `GAME_ORIGINAL`, 확인이 더 필요한 해석은 `INTERPRETATION_PENDING`으로 분리한다.
3. 원작에 없는 적중 횟수, 게이지, 쿨타임과 키 배치를 원작 조건처럼 설명하지 않는다.
4. 구현 전 발동 조건, 대상 수, 영역과의 상호작용을 먼저 확인한다.
5. 기능 검증용 VFX와 최종 연출을 구분한다.
6. 서로 강하게 연결된 2~3개 작업은 한 묶음으로 구현하되 테스트 항목은 분리한다.
7. 사용자가 문제를 발견하면 해당 문제를 고치면서 다음 계획 작업도 함께 진행한다.
8. 작업 묶음이 끝나면 이 문서를 반드시 갱신한다.

세부 원작 규칙은 `docs/CANON_SKILL_RULES.md`를 따른다.

## 4. Python/Pygame 완료 상태

사용자가 아래 네 캐릭터의 영역전개 입력을 로컬에서 정상 작동한다고 확인했다.

```text
고죠 사토루
V 또는 음성 → 우클릭 유지 → 좌클릭 → 초록 구간에서 우클릭 해제
→ 무량공처

스쿠나(이타도리 몸)
V 또는 음성 → E 유지 → 좌·우클릭 동시 입력/해제
→ 복마어주자

후시구로 메구미
V 또는 음성 → Q 유지 → 아래 드래그 → 좌우 전개 → 해제
→ 감합암예정

옷코츠 유타(본편 2학년)
V 또는 음성 → C 반지 연결 → 검을 뽑는 위쪽 드래그
→ 진안상애
```

Python 구조:

```text
characters/<character_id>/
├─ definition.py
├─ controller.py
├─ input.py
└─ effect.py
```

- 일본어 Vosk 음성인식 정상 확인
- `료이키 텐카이`까지만 음성으로 요구
- 실제 영역은 선택 캐릭터와 고유 장인 입력이 결정
- 본편 유타와 주술회전 0 유타는 별도 캐릭터로 분리

상세 구조는 `docs/ARCHITECTURE.md`와 캐릭터 설정 카드를 참고한다.

## 5. Unity 공통 조작

```text
WASD   이동
SPACE  회피 및 짧은 무적
TAB    가까운 적 락온 → 다음 적 → 해제
LMB    3단 기본 공격
Q      고죠 술식순전 「창」
E      고죠 술식반전 「혁」
R      고죠 허식 「자」
V      영역전개 입력 시작
X      진행 중인 영역 입력 취소
ENTER  승패 후 재시작
```

입력 키 정의는 `unity/Assets/Scripts/Core/CombatInputBindings.cs`에서 관리한다.

## 6. 사용자가 마지막으로 정상 확인한 Unity 상태

아래 항목까지 사용자가 Unity에서 정상 작동을 확인했다.

### 기본 전투

- WASD 이동
- 좌클릭 1타 → 2타 → 3타 공격 연계
- 허공 공격 `ATTACK CHAIN`과 실제 적중 `HIT COMBO` 분리
- 기본 공격 피해, 경직, 넉백
- 주령 추적과 근접 공격
- 주령 공격 전 주황색 예고와 `DODGE!`
- SPACE 회피와 짧은 무적
- HP HUD, 승패, ENTER 재시작

### 맵과 다중 적

- 약 65×65로 확장되는 런타임 전투장
- 가장자리 낮은 안전벽
- Y=-12 아래 낙사 즉사 안전장치
- 주령 두 마리 런타임 생성
- 주령별 체력바와 `CURSES LEFT`
- 한 마리 처치 후 전투 계속
- 모든 주령 처치 시 승리

### 락온

- TAB으로 가까운 주령 → 다음 주령 → 해제
- 대상 발밑 황금색 회전 링
- 대상 사망/거리 이탈 시 자동 해제
- 기본 공격과 허식 자가 락온 방향 우선

### 고죠 술식

- Q 술식순전 「창」
- E 술식반전 「혁」
- Q 적중 후 같은 대상에게 E 적중 시 `BLUE → RED CHAIN` 게임용 보너스
- 허식 자의 준비 조건은 적중이 아니라 Q/E 사용 자체
- R 허식 「자」
- V → 우클릭 유지 → 좌클릭 → 타이밍 해제 무량공처
- V 영역 입력 중 Q/E/R 차단
- X 영역 입력 취소

### 원작 방향 수정

- 창은 고죠 몸 중심 단순 원형 흡인이 아니라 락온 대상 근처 또는 전방의 수렴점으로 변경
- 혁은 창과 같은 원형 판정의 색 변경이 아니라 전방 반발 판정으로 변경
- 허식 자 준비와 창→혁 적중 보너스를 별도 시스템으로 분리

## 7. 현재 원격 저장소의 새 작업 — 사용자 테스트 필요

아래 묶음은 GitHub `master`에 반영됐지만 아직 사용자의 Unity 실행 확인 전이다.

### 7-1. 짧은 술식 시전 시간

- Q 창: 약 0.24초 준비 후 생성
- E 혁: 약 0.30초 준비 후 발사
- 시전 중 다른 Q/E와 R 사용 차단
- 왼쪽 스킬 UI에 시전 진행률 표시
- 현재 이동과 기본 공격까지 완전히 잠그는 행동 규칙은 아직 미완성

핵심 파일:

```text
unity/Assets/Scripts/Player/GojoTechniqueController.cs
```

### 7-2. 지속되는 창 수렴장

- 창은 약 0.95초 유지되는 별도 수렴장 오브젝트
- 피해는 대상별 한 번만 적용
- 유지 중 짧은 간격으로 수렴점 방향 인력 반복 적용
- 두 주령이 범위에 있으면 함께 수렴 가능

핵심 파일:

```text
unity/Assets/Scripts/Player/BlueConvergenceField.cs
```

### 7-3. 실제 이동하는 혁 발사체

- 혁이 고죠 정면 또는 락온 방향으로 실제 이동
- 약 11m 이동
- 경로의 적을 대상별 한 번 타격
- 일렬로 선 여러 적을 관통해 각각 밀어낼 수 있음

핵심 파일:

```text
unity/Assets/Scripts/Player/RedTechniqueProjectile.cs
```

### 7-4. 전투 오디오 기반

- 외부 음원 없이 창·혁 시전/적중 합성 효과음 생성
- `PrototypeCombatAudio`가 런타임 자동 추가
- 로컬 BGM과 대사 덮어쓰기 구조 준비
- Q/E 대사 슬롯은 발동 이벤트에 연결
- R/V 대사 슬롯은 로딩 구조만 있고 실제 이벤트 연결은 다음 작업

핵심 파일:

```text
unity/Assets/Scripts/Core/PrototypeCombatAudio.cs
docs/AUDIO_SETUP.md
```

## 8. 이번 작업 테스트 순서

```text
1. Q 입력 직후 바로 수렴점이 생기지 않고 짧은 시전 표시가 나오는지
2. 약 0.24초 뒤 수렴점이 생겨 약 1초간 유지되는지
3. 수렴장 안 주령이 지속적으로 중심으로 끌리는지
4. 한 번의 수렴장에서 같은 주령 HP가 여러 번 깎이지 않는지
5. E 입력 후 짧은 시전 뒤 빨간 발사체가 실제 앞으로 이동하는지
6. 발사체가 주령을 맞히고 진행 방향으로 밀어내는지
7. 두 주령이 일렬일 때 혁이 둘을 각각 타격하는지
8. Q/E 시전음과 적중음이 들리는지
9. 기존 창→혁 보너스가 유지되는지
10. Q/E 사용 기반 허식 자 준비가 유지되는지
11. R 허식 자와 V 무량공처가 기존처럼 작동하는지
12. Console에 빨간 컴파일 오류가 없는지
```

## 9. 오디오 로컬 파일

개인 테스트용 BGM과 대사는 아래 폴더에 둘 수 있으며 `.gitignore` 때문에 GitHub에는 올라가지 않는다.

```text
unity/Assets/Resources/LocalAudio/
```

예약 파일 이름:

```text
BGM.wav 또는 BGM.mp3
Gojo_Blue.wav
Gojo_Red.wav
Gojo_Purple.wav
Gojo_Domain.wav
```

확장자를 제외한 이름이 정확히 일치해야 한다.

- `BGM`: 전투 시작 시 반복 재생
- `Gojo_Blue`: Q 대사
- `Gojo_Red`: E 대사
- `Gojo_Purple`: R 예약 슬롯
- `Gojo_Domain`: V 예약 슬롯

원본 BGM·성우 음성 파일은 저장소에 포함하지 않는다. 개인 테스트용 파일은 로컬 폴더에만 둔다.

## 10. 알려진 한계

- 캐릭터 모델과 애니메이션 없음
- LineRenderer와 Primitive 기반 임시 VFX
- 카메라는 안정적인 고정 추적이며 회전 락온은 없음
- 주령은 NavMesh가 아닌 단순 직선 추적
- 술식 시전 중 기본 공격·이동·영역 입력의 세부 잠금 미완성
- 완성형 주력 자원과 밸런스 수치 없음
- 허식 자와 무량공처의 실제 이동/전개 연출은 임시
- 기본 공격·피격·회피·승패 사운드 없음
- Python 음성과 Unity 연결 전
- 원본 주술회전 BGM·음성은 저장소에 포함하지 않음
