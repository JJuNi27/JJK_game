# JJK Game 프로젝트 인수인계서

> 이 문서는 새 ChatGPT 대화나 새로운 개발자가 저장소 링크만 받아도 기존 대화의 맥락과 개발 결정을 이해하고 바로 이어서 작업할 수 있도록 작성한 기준 문서다.
>
> 사용자가 새 대화에서 `이 깃허브 읽고 우리 하던 거 계속하자`라고 말하면 **README, 이 문서, 캐릭터 설정 카드, 최신 코드를 먼저 읽고 저장소의 현재 상태를 기준으로 작업을 이어간다.**

---

## 1. 프로젝트 한 줄 정의

주술회전의 **술식 선언, 장인(손동작), 영역전개, 공간 변화 연출**을 실제 게임 입력 시스템으로 옮기는 개인 프로젝트다.

현재는 완성 게임을 바로 만들지 않고, 가장 독특한 요소인 **장인 커맨드 입력의 재미와 성공/실패 판정**을 Python + Pygame 프로토타입으로 검증하고 있다.

장기적으로는 Unity에서 캐릭터를 선택하고 봇과 싸우는 3D 전투 게임으로 확장한다.

## 3. 프로젝트가 시작된 과정

최초 아이디어는 웹캠으로 실제 장인 손동작을 인식해 무량공처 등의 영역전개 이펙트를 출력하는 컴퓨터 비전 프로젝트였다.

초기 대상:

```text
무량공처
복마어주자
감합암예정
진안상애
```

원래 계획은 MediaPipe Hand Landmarker로 손가락 landmark를 추출하고, 사용자가 직접 수집한 데이터로 RandomForest 분류기를 학습하는 방식이었다.

하지만 사용자의 웹캠이 고장났고 아이폰을 안정적으로 거치할 방법도 없어 카메라 인식은 후순위로 미뤘다. 폐기한 것이 아니라, 현재 마우스 입력을 나중에 `CameraSealInput`으로 교체할 수 있게 모듈화한다.

## 4. 확정된 장기 방향

### 4.1 메인 전투 모드

- 전투 전에 캐릭터를 선택한다.
- 선택한 캐릭터의 술식과 영역만 사용할 수 있다.
- 설정에 없는 기술을 다른 캐릭터에게 임의로 주지 않는다.
- Unity에서 플레이어 캐릭터와 봇이 싸우게 한다.
- 첫 봇은 강화학습이 아니라 상태 머신으로 만든다.

첫 Unity 전투 MVP 후보:

```text
플레이어: 고죠 사토루
상대: 단순 주령 봇 1마리
맵: 작은 전투장

기능:
- 이동
- 기본 공격
- 피격과 체력
- 봇 추적과 공격
- 무량공처 장인 커맨드
- 영역 발동 시 봇 행동 정지
- 승리/패배
```

### 4.2 자유 연습장

- 캐릭터별 장인 커맨드 연습
- 성공률, 연속 성공, 입력 시간, 타이밍 오차 확인
- 음성·마우스·미래 카메라 입력 테스트
- 영역 이펙트 확인
- 현재 Pygame 프로그램은 이 연습장의 원형이다.

### 4.3 일반 술식

현재는 영역전개 입력부터 검증하지만 최종 프로젝트에는 일반 술식도 추가한다.

```text
평상시 커맨드
→ 캐릭터 고유 술식

“료이키 텐카이” 음성
→ DOMAIN_READY
→ 캐릭터 고유 장인
→ 영역전개
```

일반 술식은 캐릭터별 영역전개 MVP가 안정된 뒤 추가한다.

## 5. 설정 운영 원칙

프로젝트는 원작 만화와 공식 애니메이션·극장판의 설정과 연출을 통합한다.

- 만화판과 애니판을 별도 게임 모드로 복잡하게 나누지 않는다.
- 공식 애니·극장판에서 추가된 연출과 기술도 포함할 수 있다.
- 팬 해석과 공식 설정을 분리한다.
- 게임 밸런스를 위해 만든 규칙은 `[GAME_ORIGINAL]`로 표시한다.
- 설정 사실은 `[OFFICIAL_CONFIRMED]`로 표시한다.
- 캐릭터를 구현하기 전에 설정 카드를 작성하고 사용자 검토 후 확정한다.

설정 카드 기본 항목:

```text
캐릭터 이름
기준 작품·몸 형태
생득술식
파생 기술
영역전개
장인 형태
음성·영창
흑섬 사용 여부
반전술식 사용 여부
대영역 기술
영역 사용 후 제약
특수 예외
근거 자료
게임 구현 범위
게임 각색 부분
사용자 검토 결과
```

## 6. 고죠 사토루 설정 상태

고죠 설정 카드는 대화에서 1차 검토를 통과했다.

핵심 구현 후보:

```text
무한
술식 순전 「창」
술식 반전 「혁」
허식 「자」
영역전개 「무량공처」
흑섬
반전술식
간이영역
낙화의 정
영역 사용 후 술식 번아웃
고위험 번아웃 강제 회복
0.2초 무량공처
```

현재 구현 범위는 **무량공처 장인 커맨드만**이다.

### 무량공처 커맨드

```text
1. V 또는 음성 “료이키 텐카이”
2. 우클릭 누르고 유지
3. 우클릭 유지 중 제한 시간 안에 좌클릭
4. 초록색 타이밍 구간에서 우클릭 해제
5. 성공 시 임시 무량공처 이펙트
```

입력의 의미:

| 입력 | 게임 속 의미 |
|---|---|
| V 또는 음성 | 영역 구축 시작 |
| 우클릭 유지 | 주력 집중과 장인 준비 |
| 좌클릭 | 검지·중지 장인 결합 |
| 타이밍 대기 | 무량공처 안정화 |
| 우클릭 해제 | 영역 개방 |

현재 판정 수치:

```text
목표 해제 시점: 0.90초
허용 오차: ±0.22초
```

사용자 1차 통계:

```text
10회 시도
8회 성공
성공률 80%
평균 해제 오차 0.123초
```

따라서 현재 수치를 유지한다.

## 7. 음성인식 결정

### 현재 방식

- 라이브러리: Vosk + sounddevice
- 모델: `vosk-model-small-ja-0.22`
- 주 명령: 일본어 `領域展開` / 료이키 텐카이
- V 키는 항상 대체 입력으로 유지한다.
- 모델이나 마이크가 없어도 게임은 종료되지 않는다.

### 오발동 방지

- 부분 인식 결과로 발동하지 않는다.
- 말이 끝난 뒤 확정 결과만 사용한다.
- 전체 문구가 허용 문구와 정확히 일치해야 한다.
- 평균 신뢰도 88% 이상이어야 한다.
- 마지막 확정 문구와 신뢰도를 화면 아래에 표시한다.

허용 표기:

```text
領域展開
りょういきてんかい
リョウイキテンカイ
```

한국어 Vosk 모델은 일본어 발음을 잘 잡지 못해 일본어 모델로 변경했다. 사용자가 로컬에서 `료이키 텐카이`가 잘 인식된다고 확인했다.

## 9. 스쿠나 설정 카드 상태

두 번째 캐릭터 후보는 료멘 스쿠나다.

문서:

```text
docs/characters/sukuna.md
```

상태:

- v0.1 초안 작성 완료
- 캐릭터 선택 화면에는 잠금 상태로 표시
- 사용자 승인 전에는 커맨드나 게임 기능을 확정하지 않음

초안의 핵심:

- 생득술식 `御厨子 / Shrine`
- 기본·조절형 참격
- 화염 계열 공격
- 복마어주자
- 두 손 장인
- 개방형 영역과 약 200m 최대 범위
- 흑섬
- 반전술식
- 영역전연
- 미허갈롱
- 번아웃 강제 회복
- 세계를 가르는 참격은 최종 단계 후보
- 십종영법술은 후시구로 유지 몸 변형으로 분리 검토

사용자에게 확인할 핵심 질문:

```text
1. 첫 스쿠나의 몸 형태
2. 첫 MVP에 십종영법술을 포함할지
3. 御厨子의 프로젝트 내 한국어 표기
4. 화염 계열 공격을 기본 스쿠나에 포함할지
5. 세계를 가르는 참격을 최종 기술로 포함할지
6. 복마어주자 커맨드를 실제 양손 입력으로 만들지
7. 음성을 “료이키 텐카이”까지만 요구할지,
   “복마어주자”까지 요구할지
```

## 11. 로컬 실행 방법

```powershell
git pull origin master
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python main.py
```

PowerShell 활성화가 막히면 Command Prompt:

```bat
.venv\Scripts\activate.bat
python main.py
```

음성 모델 최초 설치:

```bash
python scripts/setup_voice_model.py
```

## 12. 바로 다음 작업 우선순위

1. 사용자가 최신 코드를 pull하고 캐릭터 카드 줄바꿈이 정상인지 확인
2. `docs/characters/sukuna.md` 설정 카드 검토
3. 사용자가 스쿠나 몸 형태와 구현 범위를 확정
4. 스쿠나 장인 커맨드 후보 A/B 중 방향 선택 또는 새 방향 설계
5. 스쿠나 전용 입력·컨트롤러·임시 이펙트 구조 설계
6. 스쿠나를 선택 가능 상태로 해금
7. 고죠와 스쿠나의 입력 구조가 공통 인터페이스로 동작하는지 회귀 테스트

### 다음 작업 시 주의사항

- 고죠의 현재 조작감을 깨뜨리지 않는다.
- 스쿠나를 단순히 고죠 커맨드의 색상 변경판으로 만들지 않는다.
- 스쿠나는 두 손 장인이므로 다른 조작감을 줘야 한다.
- 승인 전 설정을 코드에 확정하지 않는다.
- 최종 이펙트 제작은 여전히 후순위다.
- 작은 단계로 수정하고 매번 로컬 테스트를 받는다.

## 14. 새 ChatGPT 대화가 따라야 할 절차

사용자가 저장소 링크와 함께 `이 깃허브 읽고 우리 하던 거 계속하자`라고 하면:

```text
1. README.md 읽기
2. docs/HANDOFF.md 읽기
3. docs/characters/ 설정 카드 읽기
4. main.py, game/, game_input/, effects/ 최신 코드 읽기
5. 문서와 코드가 다른지 확인
6. 사용자에게 현재 상태와 다음 작업을 짧게 요약
7. “바로 다음 작업 우선순위”부터 진행
```

설정 관련 기능은 먼저 자료를 조사하고 설정 카드에 반영한 뒤 사용자 검토를 받는다.
