# JJK Game 프로젝트 인수인계서

> 새 ChatGPT 대화에서는 저장소의 `README.md`, 이 문서, `docs/CANON_SKILL_RULES.md`, `docs/AUDIO_SETUP.md`, `unity/README.md`와 최신 코드를 먼저 읽고 현재 상태에서 이어간다.

이 문서는 코드 작업 묶음이 끝날 때마다 현재 테스트 상태, 새 변경, 다음 작업과 주의점을 갱신하는 **단일 인수인계 기준 문서**다.

## 1. 프로젝트 정의

프로젝트명/컨셉은 **주술사 되어보기**다.

주술회전의 술식 선언, 장인(손동작), 영역전개와 전투 연출을 실제 입력 시스템으로 옮기는 개인 프로젝트다.

현재 두 축이 존재한다.

```text
Python + Pygame
- 캐릭터별 영역전개 입력 검증
- 일본어 음성인식
- 성공·실패와 연습 통계

Unity + C#
- 실제 이동·공격·회피
- 주령 봇 전투
- 일반 술식·상위기·영역전개
- 향후 Python 음성과 Unity 연결
```

현재 우선순위는 **Unity 고죠 전투 프로토타입 안정화**다.

작업 루프:

```text

→ 사용자가 git pull origin master
→ 사용자 컴퓨터의 Unity에서 실행
→ 화면·오류·조작감 전달
→ 문제 수정과 다음 계획 작업을 함께 진행
```

사용자 명령:

```powershell
cd D:\GitHub\JJK_game
git pull origin master
```

Assistant는 Unity를 직접 실행·컴파일했다고 주장하지 않는다. 실제 실행 확인은 사용자가 담당한다.

## 3. 구현 운영 원칙

1. 원작 만화와 공식 애니메이션·극장판 설정을 우선한다.
2. 공식 조건은 `OFFICIAL_CONFIRMED`, 게임용 각색은 `GAME_ORIGINAL`, 확인이 더 필요한 해석은 `INTERPRETATION_PENDING`으로 분리한다.
3. 원작에 없는 적중 횟수, 게이지, 쿨타임과 키 배치를 원작 조건처럼 설명하지 않는다.
4. 구현 전 발동 조건, 대상 수, 영역과의 상호작용을 먼저 확인한다.
5. 기능 검증용 VFX와 최종 연출을 구분한다.
6. 서로 강하게 연결된 2~3개 작업은 한 묶음으로 구현하되 테스트 항목은 분리한다.
7. 사용자가 문제를 발견하면 해당 문제를 고치면서 다음 계획 작업도 함께 진행한다.
8. 작업 묶음이 끝나면 이 문서를 반드시 갱신한다.

세부 원작 규칙은 `docs/CANON_SKILL_RULES.md`를 따른다.

## 4. Python/Pygame 완료 상태

사용자가 아래 네 캐릭터의 영역전개 입력을 로컬에서 정상 작동한다고 확인했다.

```text
고죠 사토루
V 또는 음성 → 우클릭 유지 → 좌클릭 → 초록 구간에서 우클릭 해제
→ 무량공처

스쿠나(이타도리 몸)
V 또는 음성 → E 유지 → 좌·우클릭 동시 입력/해제
→ 복마어주자

후시구로 메구미
V 또는 음성 → Q 유지 → 아래 드래그 → 좌우 전개 → 해제
→ 감합암예정

옷코츠 유타(본편 2학년)
V 또는 음성 → C 반지 연결 → 검을 뽑는 위쪽 드래그
→ 진안상애
```

- 일본어 Vosk 음성인식 정상 확인
- `료이키 텐카이`까지만 음성으로 요구
- 실제 영역은 선택 캐릭터와 고유 장인 입력이 결정
- 본편 유타와 주술회전 0 유타는 별도 캐릭터로 분리

상세 구조는 `docs/ARCHITECTURE.md`와 캐릭터 설정 카드를 참고한다.

## 5. Unity 공통 조작

```text
WASD   이동
SPACE  회피 및 짧은 무적
TAB    가까운 적 락온 → 다음 적 → 해제
LMB    3단 기본 공격
Q      고죠 술식순전 「창」
E      고죠 술식반전 「혁」
R      고죠 허식 「자」
V      영역전개 입력 시작
X      진행 중인 영역 입력 취소
ENTER  승패 후 재시작
```

입력 키 정의는 `unity/Assets/Scripts/Core/CombatInputBindings.cs`에서 관리한다.

## 6. 사용자가 마지막으로 정상 확인한 Unity 상태

아래 항목까지 사용자가 Unity에서 정상 작동을 확인했다.

### 기본 전투

- WASD 이동
- 좌클릭 1타 → 2타 → 3타 공격 연계
- 허공 공격 `ATTACK CHAIN`과 실제 적중 `HIT COMBO` 분리
- 기본 공격 피해, 경직, 넉백
- 주령 추적과 근접 공격
- 주령 공격 전 주황색 예고와 `DODGE!`
- SPACE 회피와 짧은 무적
- HP HUD, 승패, ENTER 재시작

### 맵과 다중 적

- 약 65×65 런타임 전투장
- 가장자리 낮은 안전벽
- Y=-12 아래 낙사 즉사
- 주령 두 마리 런타임 생성
- 주령별 체력바와 `CURSES LEFT`
- 한 마리 처치 후 전투 계속
- 모든 주령 처치 시 승리

### 락온과 술식

- TAB으로 가까운 주령 → 다음 주령 → 해제
- 대상 발밑 황금색 회전 링
- 기본 공격과 허식 자의 락온 방향 우선
- 창은 락온 대상 근처 또는 전방 수렴점
- 혁은 전방 반발 판정
- Q 적중 후 같은 대상에게 E 적중 시 `BLUE → RED CHAIN`
- 허식 자 준비는 적중이 아니라 Q/E 사용 자체
- R 허식 「자」
- V 장인 입력과 무량공처
- V 입력 중 Q/E/R 차단, X 입력 취소

### 직전 작업 묶음

사용자가 직전 묶음도 정상이라고 확인했다.

- Q 약 0.24초 시전 후 약 0.95초 유지되는 창 수렴장
- 창 피해는 대상별 한 번, 인력은 유지 중 반복
- E 약 0.30초 시전 후 실제 이동하는 혁 발사체
- 혁은 일렬로 선 여러 적을 관통 가능
- 창·혁 시전음과 첫 적중 합성 효과음
- 기존 창→혁 보너스와 허식 자 준비 유지

## 7. 현재 원격 저장소의 새 작업 — 사용자 테스트 필요

아래 묶음은 GitHub `master`에 반영됐지만 아직 사용자의 Unity 실행 확인 전이다.

### 7-1. 전투 사운드 2차

현재 추가 연결:

- 기본 공격 휘두름과 적중
- 플레이어 피격
- SPACE 회피
- R 허식 자 실제 발동
- V 무량공처 입력 성공 후 실제 전개
- 승리와 패배

허식 자와 무량공처는 키 입력이 아니라 각각의 런타임 시각효과가 비활성 → 활성으로 바뀌는 순간을 감지해 재생한다.

핵심 파일:

```text
unity/Assets/Scripts/Core/PrototypeCombatAudio.cs
docs/AUDIO_SETUP.md
```

### 7-2. 술식 시전 중 행동 잠금

- Q/E 시전 중 좌클릭 기본 공격 차단
- Q/E 시전 중 새 회피 시작 차단
- Q/E 시전 중 V 영역 입력 시작 차단
- R은 기존 `CanUseUltimate` 조건으로 시전 중 차단
- 시전 중 이동은 완전 정지가 아니라 기본 속도의 약 35%로 감소
- 이미 시작된 회피 도중의 처리와 더 정교한 캔슬 규칙은 추후 조정 가능

핵심 파일:

```text
unity/Assets/Scripts/Player/BasicAttack.cs
unity/Assets/Scripts/Player/ThirdPersonPlayerController.cs
unity/Assets/Scripts/Player/GojoDomainController.cs
```

### 7-3. 전투 카메라·화면 피드백

- 기본 공격 적중, 피격, 창·혁, 허식 자, 무량공처, 승패에 강도별 위치 흔들림
- 적중 기술 색상에 맞는 짧은 화면 플래시
- 카메라 회전은 건드리지 않음
- 3타, 혁, 허식 자는 일반 타격보다 강한 피드백

핵심 파일:

```text
unity/Assets/Scripts/Camera/SimpleCameraFollow.cs
unity/Assets/Scripts/Core/PrototypeCombatAudio.cs
```

## 8. 이번 작업 테스트 순서

```text
1. 좌클릭 허공 공격에도 휘두름 소리가 나는지
2. 적중 시 별도 타격음과 약한 카메라 흔들림이 생기는지
3. 3타 적중 피드백이 1·2타보다 강한지
4. 주령에게 맞으면 피격음, 붉은 플래시, 흔들림이 생기는지
5. SPACE 회피 시작 시 효과음이 나는지
6. Q/E 시전 중 좌클릭 공격과 새 회피가 시작되지 않는지
7. Q/E 시전 중 V를 눌러도 영역 입력이 시작되지 않는지
8. 시전 중 이동 속도가 느려지되 완전히 멈추지는 않는지
9. R 허식 자 실제 발동 시 대사 슬롯/합성음과 보라색 플래시가 나는지
10. 무량공처 성공 시 대사 슬롯/합성음과 청색 플래시가 나는지
11. 모든 주령 처치 시 승리음, 플레이어 사망 시 패배음이 한 번만 나는지
12. 기존 창·혁·자·영역·락온·다중 적 기능이 유지되는지
13. Console에 빨간 컴파일 오류가 없는지
```

## 10. 알려진 한계

- 캐릭터 모델과 애니메이션 없음
- LineRenderer와 Primitive 기반 임시 VFX
- 카메라는 안정적인 고정 추적이며 회전 락온은 없음
- 주령은 NavMesh가 아닌 단순 직선 추적
- 정교한 공격 캔슬, 피격 경직 중 입력 제한은 미완성
- 완성형 주력 자원과 밸런스 수치 없음
- Python 음성과 Unity 연결 전
- 원본 주술회전 BGM·음성은 저장소에 포함하지 않음

## 11. 새 작업이 정상일 때 다음 우선순위

```text
전투 자원 시스템
- 고죠 주력 자원
- 기술별 소비와 자연 회복
- 육안/효율 특성의 게임용 해석

전투 상태 시스템
- 공통 스킬 인터페이스
- 피격 경직·시전·회피·영역의 공통 행동 상태
- 캐릭터 교체를 위한 데이터 분리

고죠 마무리
- 허식 자 실제 이동/충돌 연출 개선
- 무량공처 번아웃과 영역 종료 후 상태
- 정식 VFX·애니메이션 전 교체 가능한 구조

그 뒤
- 두 번째 캐릭터 구현 후보 확정
```

## 12. 새 채팅에서 Assistant가 먼저 할 일

1. 이 문서를 읽는다.
2. 사용자가 7번의 새 작업을 pull하고 테스트했는지 확인한다.
3. 오류가 있으면 고치면서 다음 계획 작업도 함께 진행한다.
4. 원작 조건은 `docs/CANON_SKILL_RULES.md`와 공식 자료를 다시 확인한다.
5. 작업 후 이 문서를 반드시 갱신한다.
