### 공통 언어와 차이

확인된 공통 언어는 **검은 면적을 가진 찢긴 충돌핵, 붉은 경계/줄기, 굵은 큰 가지와 가는 후행 분기, 흰 짧은 압력, 검은 점·조각 잔류**다. 붉은 bloom만 강한 효과가 아니다. 큰 가지는 직선/각진 꺾임/곡선이 섞이고, 가늘어져 사라지는 부분과 강하게 드러나는 부분이 계속 교체된다.

캐릭터 차이는 주로 타격 limb/무기 축, 접촉 높이, 방향, 준비 자세, 카메라/컷인, 선행 청록·보라 에너지다. 우리 공통 VFX는 이 색·형태 family를 공유하되 방향·규모·타이밍을 타격 데이터로 바꿔야 한다. 선행 기술색이나 인물 컷인을 모두 공통 레이어로 합치지 않는다. 화면에 보이는 2D 잉크의 인상은 참고하되 실제 자유 카메라에서 평면 카드 한 장으로 읽히게 만들지 않는다.

## 4. 사용자 확정 방향 — 구현 제안과 구분

다음은 이번 요청에서 사용자가 확정한 규칙이다. 아직 완성 VFX의 USER VERIFIED 판정은 아니다.

1. 강한 접촉 충격광.
2. 검은 주력 충돌핵.
3. 굵고 불규칙하게 갈라지는 붉은 번개.
4. 공간이 일그러지는 충격파.
5. 검은 연기와 붉은 잔광.
6. 짧은 화면 반전.
7. 기존 타격음·국소 히트스톱·카메라와 동기화.

목표: **검은 주력이 타격 지점에서 폭발해 공간을 뒤트는 인상**. 검정과 붉은 가지가 함께 입체 silhouette를 만든다. 원작 흑섬 정체성이 우선이며 Strikeborn급 이상 밀도는 장기 목표다. 이번 두 영상으로 Strikeborn과의 품질 우열을 측정한 것은 아니다. 원본 asset/code를 추출해 복제하지 않는다.

## 5. 최소 공통 구성 — 이하 구현 아이디어/초기 비교 제안

기존 전투 엔진에 별도 VFX observer와 작은 데이터 프로필을 붙이는 방향을 우선한다. 거대한 공통 VFX 시스템이나 VFX Graph 전환부터 요구하지 않는다. F 아우라의 Shader/Geometry/Profile을 복제·변형해 충돌핵으로 쓰지 않는다.

| 층 | 권장 역할과 형태 | 실패 조건 |
|---|---|---|
|충격광|접촉점에서 즉시 읽히는 짧은 흰 균열/별광. 넓은 압력보다 먼저 peak|오래 남는 흰 원판, 전체 effect가 흰빛에 지워짐|
|검은 충돌핵|단단한 검정 면적과 찢긴 비대칭 외곽, 앞뒤 깊이가 있는 급팽창/붕괴|매끈한 검정 구체, 둥근 연기만 보임, 얇은 검정 판|
|붉은 큰 가지+분기|굵기 차이·분기·빈 구간·깊이를 가진 큰 흐름. 같은 경로의 검은 윤곽/붉은 면/짧은 흰 hotspot|평행 케이블 묶음, 일정 굵기의 긴 선, 네 방향 대칭, 분리된 검정 조각|
|충격파|타격 축으로 찌그러져 퍼지는 불완전한 압력/굴절 인상. 앞뒤 교차|카메라 정면의 완전 원형 disc·바닥 장판|
|연기/잔광|색 복귀 뒤 작은 검은 질량과 일부 붉은 분기가 분리·감속·소멸|주력 아우라로 변함, 다음 콤보·숫자를 오래 가리는 검은 벽|

모든 층의 peak를 길게 겹치지 않는다. 접촉 순간에는 큰 검정/붉은 형태가 한 덩어리로 읽히고, 직후에는 경계·분기·연기 중 일부만 남아 압력의 방출을 읽히게 한다. 메시/strip을 쓴다면 앞뒤/높이 방향으로 분포하고 한 카메라에만 맞춘 평면을 본체로 삼지 않는다. Billboard의 제한적 광/연기 사용과 실제 3D 전체 실루엣을 구분한다. 재사용 풀과 유한 수명은 후보이며 별도 구현 검증이 필요하다.

### 시간과 규모 — 관측값이 아닌 튜닝 출발안

일반 단발 비교 후보는 접촉광0.03~0.06초, 검정/붉은 peak 약0.08~0.18초, 큰 가지 약0.12~0.30초, 흐려지는 잔류 약0.35~0.65초다. 화면 변화는 별도로 **약0.06~0.10초부터 비교**할 수 있다. 영상에서 확인한 흑백1프레임(나나미)과4프레임(고죠/로블 피니셔)은 서로 달라 하나의 고정 시간을 그대로 복사할 근거가 아니다. 위 수치는 승인된 기본값이나 기존 hit-stop 변경 지시가 아니다.

임팩트 밀도는 충분히 강하게 시작하되 단순 광량·파티클 수로 채우지 않는다. 초기 카메라 거리에서 타격점 주변 약캐릭터 키1~1.5배의 비대칭 본체와 더 멀리 뻗는 일부 가지를 비교하는 것을 제안한다. 스케일은 월드 타격 크기/타깃 크기를 기준으로 하고 숫자 크기나 피해량에 직접 연결하지 않는다. 최종 값·특별 연출의 지속시간은 사용자 비교 후 결정한다.

## 6. 연속 흑섬 합성 규칙 — 확정 의도와 설계 제안

**확정 의도:** 유효 이벤트마다 본체 VFX가 발생하고, 화면 반전·카메라·히트스톱 누적으로 장시간 전장을 가리지 않는다. 새로운 정상 이벤트를 중복으로 버리지 않는다.

**제안:** 월드 impact 인스턴스는 피해 결과 키별로 수락한다. 화면 효과는 카메라별로 여러 pulse를 한 envelope로 합성하되 강도 상한과 빠른 복귀를 둔다. pulse duration을 단순 더하거나 매번 긴 암전 전체를 재시작하지 않는다. 긴 잔류는 외곽/투명도/수명 예산으로 관리하고 새 접촉광과 굵은 가지를 우선한다. camera impulse는 방향별로 합성·제한하고 기본 yaw/pitch에 누적 기록하지 않는다.

합성이 필요한 초고밀도 타격에서는 각각의 전면 반전을 모두 시간상 분리해 보여 줄 수 없다. 이벤트별 접촉광·검정/붉은 peak와 이벤트 수락 기록은 유지하고, 겹치는 전면 pulse만 합성하는 방식으로 검증한다. FPS 저하/슬롯 포화에서 어떤 잔류가 교체됐는지도 기록해 이벤트 누락과 의도된 합성을 구분해야 한다. 구체적인 강도·연속 노출 상한은 미확정이다.

기존 hit-stop은 `Math.Max(현재 종료, 현재 unscaled 시각+duration)` 방식으로 국소 관리된다. 이번 VFX를 이유로 같은 타격의 hit-stop을 두 번 요청하거나 전역 Time.timeScale을 바꾸지 않는다. 별도 강화가 필요하면 사용자 승인을 받는다.

### 주의할 실제 순서와 빠진 데이터

- `Health.ReceiveDamage`의 Died 콜백 → `ShibuyaMatch.OnDeath`의 양쪽 StopCombat이 **Resolved 이전**에 실행될 수 있다. 양수 피해 snapshot을 받은 뒤 현재 타깃이 죽었거나 전투가 끝났다는 이유만으로 이미 성립한 마지막 흑섬을 버리면 안 된다. 마지막 월드 impact는 재생하고 기존 승패/재시작 정책은 변경하지 않는 방향을 제안한다. 특별 카메라를 계속할지/종료할지는 별도 정책이 필요하다.
- `WorldPoint`는 현재 타깃 위치+작성된 attackHeight이며 정밀 mesh 접촉점/법선이 아니다. 결과에는 타격 방향, Presentation 등급, 프로필 참조, 사운드 정보가 없다. H0에서는 receipt 시 source→victim/attacker forward로 시각 기준축을 동결하는 최소안을 검토할 수 있지만 실제 접촉 법선이라고 설명하지 않는다. 캐릭터별 정확한 방향/특별 profile이 필요하면 타격 데이터의 시각 snapshot 최소 확장을 별도 합의한다.
- `Resolved`는 일반 hit-stop/HitConfirmed보다 먼저 발행된다. H0는 같은 프레임에 본체를 시작할 수 있으나 H1이 LastHitSoundPitch/카메라 상태를 이 순간 이미 갱신됐다고 가정하면 이전 타격 값을 읽을 수 있다. 즉시 기록한 이벤트 맥락과 기존 hit-confirm의 순서를 맞추며 단순한 임의 delay로 동기화하지 않는다.
- 레거시 `Assets/Scripts/Core/ProductionCombatFeedbackDirector.cs`는 CombatMVP와 SimpleCameraFollow를 대상으로 한다. ShibuyaOrbitCamera에 이미 설치된 공통 연출 director로 오인해 연결하지 않는다. Gojo Purple/Domain의 전용 screen/camera를 수정하지 않는다.
- PC_Renderer 자산에는 SSAO가 있고 Mobile_Renderer의 feature 목록은 비어 있다. 조사한 목록에서 범용 흑섬 반전 pass는 확인하지 못했다. 실제 실행 quality/renderer와 HUD 전후 처리 순서를 H1에서 확인한 뒤 카메라 한정 방식을 선택한다. 전 프로젝트 renderer를 무조건 교체하지 않는다. 기존 IMGUI 숫자/HUD까지 반전시키는 정책은 승인되지 않았다.

## 9. 후속 검증 계획과 미확정 사항

자동 targeted: 일반/치명은 흑섬0, 정상 흑섬 N개에 수락/월드 spawn N, 같은 key replay0, 새 action의 event0을 정상 수락, 다단·복수 타깃, OFF 숫자와 독립, 가드/패링/회피/Health 무적/특수방어/무하한 차단0, 치명적 마지막 타격1, 사망/재시작/씬 종료 시 구독/풀 정리, Resource/Zone/기존 피해값 불변. 실제 무하한 장면을 실행하지 않은 대역 검사는 그렇게 구분한다.

H1 이후: 30/60fps·큰 dt에서 시간 상한, 연속 pulse의 지속 가림 제한, 제3자 카메라 불변, 시네마틱 시작/종료와 역순 중단에서 FOV/yaw/pitch 복구, 기존 소리와 hit-stop 중복 없음, HUD/숫자/결과 패널 가독성, 실제 renderer/GPU/overdraw/풀 누수. 과거 전체 회귀를 작은 시각 수정마다 반복하지 않는다.

사용자 직접 검수: 밝은 중성 전장·원속도에서 정면/측면/후면/하이앵글/이동/공중의 흑섬, 어두운 배경, 반격, 빠른 다단, 동시에 다른 적과의 전투를 본다. 검은 질량이 먼저 읽히는지, 붉은 가지가 평면/케이블로 보이지 않는지, 다음 행동 전에 시야가 복귀하는지 판단한다. 일반/특별은 같은 피해 조건으로 비교한다. 숫자 횟수의 기술 PASS가 최종 VFX 품질 USER VERIFIED를 대신하지 않는다.
