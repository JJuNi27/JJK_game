# 새 채팅 인수인계 — JJK Game

이 문서는 새 ChatGPT 채팅에서 프로젝트를 바로 이어가기 위한 기준 문서입니다. 코드 작업 묶음이 끝날 때마다 현재 상태, 테스트 결과, 다음 작업과 주의점을 갱신합니다.

## 사용자와 작업 방식

- 사용자: 박민준
- GitHub 저장소: `JJuNi27/JJK_game`
- 작업 브랜치: `master`
- 사용자 로컬 저장소: `D:\GitHub\JJK_game`
- Unity 프로젝트: `D:\GitHub\JJK_game\unity`
- Unity: 6.3 LTS `6000.3.20f1`, URP
- 사용자가 문제를 발견하면 해당 문제를 수정하면서 다음 계획 작업도 함께 진행합니다.
- Assistant가 `master`에 코드를 올리고, 사용자가 아래 명령으로 받은 뒤 Unity에서 직접 테스트합니다.

```powershell
cd D:\GitHub\JJK_game
git pull origin master
```

Assistant는 Unity를 직접 실행·컴파일했다고 주장하지 않습니다. 실제 실행 확인은 사용자가 담당합니다.

## 제작 방향

프로젝트명/컨셉은 ‘주술사 되어보기’이며, 현재는 고죠 사토루 대 주령 전투를 캡슐 형태로 검증하는 Unity 프로토타입입니다.

중요 원칙:

1. 원작 발동 조건과 게임용 각색을 구분합니다.
2. `docs/CANON_SKILL_RULES.md`의 `OFFICIAL_CONFIRMED`, `GAME_ORIGINAL`, `INTERPRETATION_PENDING` 표기를 따릅니다.
3. 원작에 없는 적중 횟수·게이지·쿨타임을 원작 조건처럼 설명하지 않습니다.
4. 기능 검증용 VFX와 최종 연출을 구분합니다.
5. 서로 강하게 연결된 2~3개 작업은 한 묶음으로 구현하되 테스트 항목은 분리합니다.

## 현재 공통 조작

```text
WASD   이동
SPACE  회피 및 짧은 무적
TAB    가까운 적 락온 → 다음 적 → 해제
LMB    3단 기본 공격
Q      고죠 술식순전 「창」
E      고죠 술식반전 「혁」
R      고죠 허식 「자」
V      영역전개 입력 시작
X      진행 중인 영역 입력 취소
ENTER  승패 후 재시작
```

## 사용자가 마지막으로 정상 확인한 상태

아래 항목까지 사용자가 Unity에서 정상 작동을 확인했습니다.

- WASD 이동, 기본 공격 3단 연계와 실제 적중 콤보 분리
- 주령 공격 예고, DODGE UI, SPACE 회피 무적
- Q 창, E 혁, 창→혁 적중 보너스
- 허식 자의 준비 조건이 적중이 아닌 Q/E 사용 자체로 분리됨
- R 허식 자와 V 무량공처
- 낙사 즉사와 승패 처리
- TAB 락온, 락온 대상 우선 기본 공격/허식 자 조준
- 주령 두 마리 생성, TAB 대상 전환, 모든 적 처치 시 승리
- 약 65×65 확장 맵과 낮은 안전벽
- 창은 락온 대상 근처 또는 전방 수렴점, 혁은 전방 반발 판정으로 분리

## 현재 원격 저장소의 새 작업 — 아직 사용자 테스트 필요

이번 작업 묶음은 사용자가 아직 실행 확인하지 않았습니다.

### 1. 짧은 술식 시전 시간

- Q 창: 약 0.24초 준비 후 생성
- E 혁: 약 0.30초 준비 후 발사
- 시전 중에는 다른 Q/E 및 R 사용이 차단됨
- 왼쪽 스킬 UI에 시전 진행률 표시

### 2. 지속되는 창 수렴점

- 창은 약 0.95초 유지되는 별도 수렴장 오브젝트로 생성됨
- 피해는 대상별 한 번만 적용
- 유지되는 동안 짧은 간격으로 수렴점 방향의 인력을 반복 적용
- 두 주령이 범위에 있으면 함께 수렴 가능

관련 파일:

```text
unity/Assets/Scripts/Player/BlueConvergenceField.cs
```

### 3. 실제 이동하는 혁 발사체

- 혁이 고죠 정면 또는 락온 방향으로 실제 이동
- 약 11m를 이동하며 경로의 적을 대상별 한 번 타격
- 일렬로 선 여러 적을 관통해 각각 밀어낼 수 있음

관련 파일:

```text
unity/Assets/Scripts/Player/RedTechniqueProjectile.cs
```

### 4. 전투 오디오 기반

- 외부 파일 없이 창·혁 시전/적중 합성 효과음 재생
- `PrototypeCombatAudio`가 런타임에 자동 추가됨
- 로컬 BGM과 대사 덮어쓰기 구조 준비
- 세부 안내: `docs/AUDIO_SETUP.md`

관련 파일:

```text
unity/Assets/Scripts/Core/PrototypeCombatAudio.cs
```

## 이번 작업 테스트 순서

```text
1. Q 입력 직후 바로 수렴점이 생기지 않고 짧은 시전 표시가 나오는지
2. 약 0.24초 뒤 수렴점이 생겨 약 1초간 유지되는지
3. 수렴장 안 주령이 지속적으로 중심 쪽으로 끌리는지
4. 한 번의 수렴장에서 같은 주령 HP가 여러 번 깎이지 않는지
5. E 입력 후 짧은 시전 뒤 빨간 발사체가 실제 앞으로 이동하는지
6. 발사체가 주령을 맞히고 진행 방향으로 밀어내는지
7. 두 주령이 일렬일 때 혁이 둘을 각각 타격하는지
8. Q/E 시전음과 적중음이 들리는지
9. 기존 창→혁 보너스와 Q/E 사용 기반 허식 자 준비가 유지되는지
10. Console에 빨간 컴파일 오류가 없는지
```

## 오디오 로컬 파일

개인 테스트용 BGM과 대사는 아래 폴더에 둘 수 있으며 GitHub에는 올라가지 않습니다.

```text
unity/Assets/Resources/LocalAudio/
```

예약 이름:

```text
BGM
Gojo_Blue
Gojo_Red
Gojo_Purple
Gojo_Domain
```

현재 Q/E 대사는 실제 이벤트에 연결되어 있습니다. R 허식 자와 V 무량공처 대사 슬롯은 로딩 구조만 있고 발동 이벤트 연결은 다음 오디오 작업에 남아 있습니다.

## 알려진 한계

- 캐릭터 모델과 애니메이션 없음
- 현재 VFX는 런타임 LineRenderer/Primitive 기반 임시 연출
- 카메라는 안정적인 고정 추적이며 회전 락온은 아직 없음
- 주령은 NavMesh가 아닌 단순 직선 추적
- 기본 공격 중 술식 시전 같은 세부 행동 잠금 규칙은 아직 완성되지 않음
- 완성형 주력·쿨타임·밸런스 수치가 아님
- 원본 주술회전 BGM·음성은 저장소에 포함하지 않음
